GUION DE SORPRESAS, 01 repaso de C++ desde cero

Complemento del GUION.md de esta carpeta. Para cada fichero: que les
puede sorprender, como lo enseno en directo y que idea se tienen que
llevar. Todas las salidas estan comprobadas con g++ 13.3 en Linux,
C++20, perfil Debug y -Wall -Wextra (lo mismo que pone el CMakeLists
del curso).

Como leer este guion:

   HAGO      -> lo que tecleo o cambio delante de ellos
   PREGUNTO  -> lo que lanzo a la clase ANTES de ejecutar
   SALE      -> lo que aparece por pantalla
   DIGO      -> la idea que se tienen que llevar
   -> HILOS  -> conecta con algo de las carpetas de hilos; decirlo aunque
                vaya con prisa

Si voy justo de tiempo, lo imprescindible es: 05, 07, 08, 09, 15 y todo
lo marcado con -> HILOS.

Despues de cada cambio en directo, DESHAGO el cambio antes de pasar al
siguiente punto.


---------------------------------------------------------------------
LO QUE DIGO EL PRIMER DIA: LAS CUATRO FORMAS DE FALLAR EN C++
---------------------------------------------------------------------

   ERROR     -> no compila. No se ejecuta NADA.
   AVISO     -> (warning) compila y se ejecuta igual. Sale en la ventana
                de compilacion y es muy facil no verlo.
   CUELGUE   -> compila, arranca y revienta a mitad. CLion lo dice al
                final, por ejemplo:
                Process finished with exit code 139 (interrupted by signal 11:SIGSEGV)
   SILENCIO  -> compila, no avisa, no revienta... y el resultado esta
                MAL. En C++ pasa mucho mas que en Python.

   Codigos que van a salir hoy:
      132 SIGILL   instruccion ilegal (funcion sin return)
      134 SIGABRT  el programa se aborta a si mismo (.at fuera de rango)
      136 SIGFPE   division entera entre cero
      139 SIGSEGV  memoria que no es tuya (puntero nulo, variable muerta)
   En Windows los numeros son otros, pero la idea es la misma.

FICHERO 01_variables_y_tipos.cpp
=====================================================================

[01.1] Un error de compilacion no deja ejecutar NADA

   HAGO: quito el ; de   int edad = 20;
   PREGUNTO: "Se imprimira algo antes de fallar?"
   SALE: error: expected ',' or ';' before 'double'      (linea 18)
         error: 'nota' was not declared in this scope    (linea 31)
         y no se ejecuta ni una linea
   DIGO: el compilador revisa el fichero entero antes de crear el
         programa. Dos cosas mas: marca el error en la linea SIGUIENTE
         (donde se da cuenta), y un fallo arrastra otros detras.
         Arreglad siempre el PRIMER error de la lista.

[01.2] Un cuelgue en ejecucion SI deja pasar lo anterior

   HAGO: justo antes del cout de nombre anado:
            int cero = 0;
            cout << "division: " << edad / cero << "\n";
   PREGUNTO: "Compila? Que sale?"
   SALE: compila sin avisos, y:
         edad: 20
         nota: 7.5
         letra: A
         aprobado: 1   (true se imprime como 1)
         Process finished with exit code 136 (interrupted by signal 8:SIGFPE)
   DIGO: el compilador no sabe cuanto vale cero hasta que el programa
         corre. Hay errores "antes de empezar" (compilacion) y cuelgues
         "a mitad de camino" (ejecucion). El segundo deja hecho todo lo
         anterior.
   OJO: en Windows puede que no salga ni lo anterior: la salida se queda
        en espera y se pierde con el cuelgue.

[01.3] La caja SI tiene tipo, y lo que no cabe se corta

   HAGO: edad = edad + 1;   por   edad = "veinte";
   SALE: error: invalid conversion from 'const char*' to 'int'
   HAGO: ahora   int edad = 20.7;
   PREGUNTO: "Error, aviso, o que?"
   SALE: ni error ni aviso:
         edad: 20
   DIGO: al contrario que en Python, el tipo de la caja no cambia nunca.
         Y si metes un decimal en un int, lo corta sin decir nada.
         Con llaves,  int edad{20.7};  SI da error (narrowing conversion).

[01.4] Comillas simples y dobles no son lo mismo

   HAGO: char letra = "A";
   SALE: error: invalid conversion from 'const char*' to 'char'
   HAGO: char letra = 'AB';
   SALE: dos avisos (multi-character character constant) y
         letra: B
   DIGO: simples, UN caracter. Dobles, texto. Y un aviso no es un adorno:
         ha compilado y el valor esta mal.

[01.5] Una variable sin valor tiene basura

   HAGO: int edad;          (quito el = 20)
   PREGUNTO: "Que valdra edad? Cero?"
   SALE: aviso: 'edad' is used uninitialized
         edad: 32753
   HAGO: ejecuto otra vez
   SALE: edad: 32600        (otro numero cada vez)
   DIGO: en Python no se puede usar una variable sin darle valor. En C++
         si, y vale lo que hubiera en esa memoria. Toda variable nace
         con valor, siempre.

[01.6] Mayusculas, bool y const

   HAGO: edad = edad + 1;   por   Edad = edad + 1;
   SALE: error: 'Edad' was not declared in this scope; did you mean 'edad'?
   HAGO: cout << true + true << "\n";
   PREGUNTO: "Cuanto vale true + true?"
   SALE: 2
   DIGO: por dentro true es 1 y false es 0. Por eso aprobado sale como 1.
   HAGO: descomento   NUM_HILOS = 8;
   SALE: error: assignment of read-only variable 'NUM_HILOS'

   -> HILOS: lo que es const no da problemas aunque lo lean mil hilos a
      la vez. Los problemas empiezan cuando alguien ESCRIBE.

=====================================================================

[02.1] El cast en el sitio equivocado

   PREGUNTO: "Y si pongo el parentesis asi:  (double) (a / b) ?"
   HAGO: cambio  (double) a / b  por  (double) (a / b)
   SALE: (double) a / b = 3
   DIGO: primero se hace lo de dentro del parentesis, entre enteros: 3.
         Convertir 3 en double da 3. El cast va ANTES de dividir.

[02.2] Guardarlo en un double no arregla nada

   HAGO: double media = a / b;          (sin cast)
   SALE: (double) a / b = 3
   HAGO: anado   double media_notas = (7 + 8) / 2;
                 cout << media_notas << "\n";
   SALE: 7
   DIGO: la parte derecha se calcula ANTES de mirar donde se guarda.
         Y fijaos: sale 3, no 3.0. cout no ensena el .0, asi que por
         pantalla no se distingue un double de un int.

[02.3] Con negativos, la division corta hacia el cero

   HAGO: int a = -7;
   PREGUNTO: "Cuanto es -7 / 2? Y -7 % 2?"
   SALE: a / b = -3
         a % b = -1
   DIGO: C++ corta hacia el cero (Python, con // y %, da -4 y 1). Y el resto puede ser
         negativo: para saber si es impar, comparad  % 2 != 0,
         nunca  % 2 == 1.

[02.4] 0.1 + 0.2 no es 0.3, y cout lo esconde   (la que mas sorprende)

   HAGO: cout << 0.1 + 0.2 << "\n";
         cout << (0.1 + 0.2 == 0.3) << "\n";
   SALE: 0.3
         0
   PREGUNTO: "Si imprime 0.3, por que la comparacion es falsa?"
   HAGO: #include <iomanip>  y  cout << setprecision(17) << 0.1 + 0.2
   SALE: 0.30000000000000004
   DIGO: el ordenador guarda los decimales en binario y no puede guardar
         0.1 exacto. cout redondea a 6 cifras al imprimir y lo tapa.
         Nunca comparar decimales con ==.

[02.5] Los enteros SI se desbordan

   HAGO: int grande = 2147483647;
         grande = grande + 1;
         cout << grande << "\n";
   PREGUNTO: "Cuanto sale?"
   SALE: -2147483648           (sin error ni aviso)
   DIGO: un int tiene sitio para unos 2100 millones. Al pasarse da la
         vuelta a los negativos. En Python no pasaba. Oficialmente C++
         no promete nada cuando pasa esto: hoy da la vuelta, manana
         quien sabe.

   -> HILOS: contador++ PARECE una operacion y son TRES: leer, sumar y
      guardar. Lo digo ya. En la carpeta 05
      (02_atomicidad_incremento_en_tres_pasos) es exactamente lo que se
      rompe.

   SALE: Suspenso

[03.2] Solo entra en la primera que se cumple

   PREGUNTO: "9.5 cumple las tres condiciones. Cuantas calificaciones

   SALE: Sobresaliente         (solo esa)
   DIGO: se entra en la PRIMERA que se cumple; las demas ni se miran. Por

[03.3] Comparaciones encadenadas: compila y miente

   HAGO: nota = 9.5  y anado   cout << (5 <= nota < 7) << "\n";
   PREGUNTO: "9.5 esta entre 5 y 7?"
   SALE: dos avisos (comparisons like 'X<=Y<=Z' do not have their

         1
   DIGO: C++ hace primero  5 <= nota  (da 1) y despues  1 < 7  (cierto).

[03.4] El punto y coma detras del if

   HAGO: int asistencia = 50;  y pongo ; detras del if del &&:
            if (nota >= 5 && asistencia >= 80); {

         Puede presentarse a la defensa
   DIGO: el ; cierra el if con un cuerpo vacio. Las llaves de debajo son
         un bloque suelto que se ejecuta siempre.

[03.5] Sin llaves, solo manda la primera linea

   HAGO: asistencia = 50, quito las llaves de ese mismo if y anado debajo,
         con la misma sangria:
            cout << "Enhorabuena\n";
   SALE: Aprobado
         Enhorabuena
         Tiene que entregar la practica
   DIGO: en C++ la sangria no significa nada; las llaves, si. Por eso en
         la asignatura llevan llaves siempre, aunque sea una linea.

   DIGO: dentro del bucle no hay cout, asi que un bucle infinito es una

   DIGO: aqui el compilador NO os salva como en el for del 04. El while

[05.4] El do-while entra aunque la condicion sea falsa

   HAGO: cambio  do { ... } while (intentos < 5);
         por     while (intentos < 5) { ... }
   PREGUNTO: "Saldra 'Dentro del do-while'?"

   HAGO: en el do-while original quito el ; de   while (intentos < 5);
   SALE: error: expected ';' before 'int'
   DIGO: el do-while es el unico bucle que termina en punto y coma.

[05.5] La bandera NO saca del bucle al momento

            if (numero % 7 == 0) {

            numero++;

   DIGO: al poner encontrado = true el resto de la vuelta SE SIGUE

   -> HILOS: cuando otro hilo cambie una bandera para parar un servidor,

[05.6] Olvidar el !

   HAGO: while (!encontrado)   por   while (encontrado)
   SALE: Primer multiplo de 7 mayor que 50: 51
   DIGO: ni error, ni aviso, ni cuelgue. El bucle no entra nunca y el

FICHERO 08_paso_por_referencia_y_puntero.cpp     *** IMPRESCINDIBLE ***
=====================================================================

[08.1] El & en el sitio equivocado

   HAGO: sumar_diez(saldo);   por   sumar_diez(&saldo);
   SALE: error: invalid conversion from 'int*' to 'int'
         error: cannot bind rvalue '(int)(& saldo)' to 'int&'
   DIGO: la referencia se pide en la FUNCION (int&). La llamada se
         escribe normal. &saldo es la direccion, y eso es para punteros.
   HAGO: al reves:   sumar_cien(&saldo);   por   sumar_cien(saldo);
   SALE: error: invalid conversion from 'int' to 'int*'

[08.2] A una referencia no se le pasa un numero suelto

   HAGO: sumar_diez(5);
   SALE: error: cannot bind non-const lvalue reference of type 'int&' to
         an rvalue of type 'int'
   DIGO: una referencia es otro nombre de una VARIABLE. Un 5 no es una
         caja: no hay donde escribir.

[08.3] Olvidar los asteriscos: compila y no hace nada

   HAGO: *puntero = *puntero + 100;   por   puntero = puntero + 100;
   PREGUNTO: "Compila? Cuanto valdra saldo?"
   SALE: sin avisos:
         Tras sumar_cien(&saldo): saldo = 110
   DIGO: sin * se suma 100 a la DIRECCION, no al valor. El puntero se va
         a apuntar a otro sitio y saldo ni se entera. (Si quito solo el
         * de la izquierda, eso si da error.)

[08.4] Un puntero que no apunta a nada

   HAGO: antes del cout de la direccion anado:
            int* nadie = nullptr;
            *nadie = 5;
   SALE: Tras sumar_diez(saldo):  saldo = 110
         Tras sumar_cien(&saldo): saldo = 210
         Process finished with exit code 139 (interrupted by signal 11:SIGSEGV)
   DIGO: nullptr significa "no apunto a nada". Escribir ahi es escribir
         en memoria que no es tuya. SIGSEGV, "segmentation fault", es el
         cuelgue mas famoso de C++.

[08.5] La direccion cambia en cada ejecucion

   HAGO: ejecuto dos veces
   SALE: Direccion de saldo: 0x7ffc5e58be44
         Direccion de saldo: 0x7ffe479e0384
   DIGO: el sistema coloca el programa en un sitio distinto cada vez (por
         seguridad, os sonara de ciberseguridad). Una direccion no se
         apunta ni se guarda: se pide con & cuando hace falta.

   -> HILOS: anado  #include <thread>  y cambio  sumar_diez(saldo);  por
            thread h(sumar_diez, saldo);
            h.join();
      SALE: un error enorme que sale de ficheros de la libreria:
            error: static assertion failed: std::thread arguments must be
            invocable after conversion to rvalues
      HAGO: thread h(sumar_diez, ref(saldo));
      SALE: saldo = 110 y 210, como siempre
      DIGO: thread copia; si la funcion pide int&, ni compila. ref(saldo)
      le dice "esta no la copies". Carpeta 03,
      05_trampa_1_solucion_std_ref. Y cuando salga un error enorme, no
      os asusteis: buscad la primera linea que nombra VUESTRO .cpp.

FICHERO 09_ambito_y_tiempo_de_vida.cpp     *** IMPRESCINDIBLE ***

[09.1] Quitar static

   HAGO: static int recuerdo = 0;   por   int recuerdo = 0;
   PREGUNTO: "Que valdra ahora en la tercera llamada?"
   SALE:   local = 1, static = 1, global = 1
           local = 1, static = 1, global = 2
           local = 1, static = 1, global = 3
   DIGO: sin static, recuerdo nace y muere en cada llamada, como local.

[09.2] Una local tapa a la global

   DIGO: en Python, para cambiar una global dentro de una funcion hacia
         falta  global contador. En C++ cualquier funcion la cambia sin
         pedir permiso. Comodo y peligroso.
   HAGO: dentro de visitar, arriba del todo:   int llamadas_totales = 0;
         y en main, detras del for:
            cout << "En main, global = " << llamadas_totales << "\n";
   PREGUNTO: "Cuanto vale la global al final?"
   SALE:   local = 1, static = 1, global = 1      (las tres veces)
         En main, global = 0
   DIGO: la local con el mismo nombre TAPA a la global. La funcion ha
         contado en su caja; la de verdad sigue a 0. Ni un aviso.

   -> HILOS: una global la ven y la tocan todos los hilos sin avisar. Es
      lo primero que se rompe (carpeta 04, 02_contador_compartido_roto).

[09.3] Una referencia a una variable que ya ha muerto

   HAGO: encima de main:
            int& dame_numero() {
                int numero = 42;
                return numero;
            }

   HAGO: quito el & de   vector<int>& numeros

   -> HILOS: para que varios hilos trabajen sobre el MISMO vector hay que

   HAGO: vector<int> resultados(3, 0);   por   resultados{3, 0};
